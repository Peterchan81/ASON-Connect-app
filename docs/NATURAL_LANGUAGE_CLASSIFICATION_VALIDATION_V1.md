- 검증 대상: `ClassificationScorer.classify()` (규칙 기반 분류기)
- 검증 일자: 2026-07-30
- 브랜치: `feature/untimed-schedule-classification`
- 근거 테스트: `test/ason_connect/natural_language_classification_validation_test.dart` (150문장, 자동 실행)

## 1. 검증 목적

ASON Connect의 자연어 입력이 실제로 일정 / 나의 하루 목표 / 다이어리 / 메모 4개
카테고리와 "분류하지 않아야 하는" 잡담·질문·과거 보고·불확실 표현을 얼마나
정확하게 구분하는지, 실제 사용자가 말할 법한 문장 150개 이상으로 종합
검증합니다. 목적은 이론적 정확성이 아니라 **V1 출시 가능 여부를 판단할 수
있는 실측 정확도**를 확보하는 것입니다.

## 4. 정확도

판정 기준(문서 전체에서 동일하게 사용):
- **정확(EXACT)**: 기대 카테고리와 실제 결과가 정확히 일치(비분류 대상은
  `isUnclassified == true`)
- **허용 가능(ACCEPTABLE)**: 문장 자체가 본질적으로 애매해 사람이 봐도 정답이
  둘 이상인 경우(예: "헬스장 등록하기"는 일정/메모 둘 다 말이 됨), 또는 모든
  카테고리 점수가 동점(0점)이라 구조상 임의 배정되는 경우(점수 1 이하)
- **오분류(MISCLASSIFIED)**: 위 어느 쪽도 아님

## 6. 수정한 규칙

**`lib/features/ason_connect/services/classification_scorer.dart`**
1. 메모 키워드에 `저장` 추가.
2. 다이어리 감정 패턴에 `(즐거운|좋은|행복한) 시간을 보냈` 관용구 추가.
3. 시간 패턴(`timePattern`)이 숫자("3시")뿐 아니라 한글 숫자("세 시")도
   인식하도록 확장. "한 시간"(소요 시간)과 헷갈리지 않도록 `시(?!간)` 부정
   전방탐색 추가.
4. 절대 달력 날짜(`3월 15일` 등) 패턴을 새로 추가해 일정 점수에 반영(상대
   날짜는 이미 반영되고 있었으나 절대 날짜는 반영되지 않고 있었음). "오늘/
   내일/어제"는 다이어리 문장에도 아주 흔해 의도적으로 제외.
5. "할 일" 카테고리에도 `UntimedScheduleClassifier.isUnlikelyToBeSchedule()`
   억제를 적용(질문/과거 완료형이면 "해야" 키워드가 있어도 할 일로 확정하지
   않음).
6. 메모의 구매/준비 동사 점수(`사야/구매/해야` 등)를
   `UntimedScheduleClassifier.isQuestionOrUncertain()`이 참이면 주지 않음
   ("서류를 제출해야 하나?"가 메모로 잘못 뽑히는 문제).

**`lib/features/ason_connect/services/untimed_schedule_classifier.dart`**
1. 질문/불확실 패턴에 `고민` 추가(기존에는 "~까?/~나요/~뭐지"류만 인식).
2. 용무 어휘 확장(기존 목록에 자연스러운 동의어만 추가):
   - 문장 끝 동사: `들르기`, `갱신하기`, `갔다 오기`
   - 문장 어디든: `갱신`(바로 명사), `[가-힣]+(한테|에게|께) 전화`(사람+전화,
     동사 없이도 인식)
   - 의무형: 기존 "가야"뿐 아니라 "보내야"도 인식(`(가야|보내야) 해/한다/
     겠/해요/합니다/하는데`)
3. `isQuestionOrUncertain()`을 공개 메서드로 분리(ClassificationScorer의
   메모 점수 억제에서 재사용).

## 7. 남은 한계

1. **캐주얼 반문형 미인식**("제출 기한이 언제까지지" 등 "-까지지"류) —
   문장 1개만을 위한 정규식 추가를 피하려고 고치지 않았습니다. 반복 사례가
   더 발견되면 다음 턴에서 검토가 필요합니다.
2. **동점 시 일정으로 임의 배정**("회의 아이디어 정리") — `DraftCommandCategory`
   열거형 선언 순서상 모든 카테고리 점수가 동점이면 `schedule`이 먼저
   나열되어 있어 항상 이깁니다. 이 검증에서 1건 발견했지만, 동점 처리
   방식 자체를 바꾸는 건 더 큰 구조 변경이라 이번 턴에서는 손대지
   않았습니다.
3. **동사·키워드가 전혀 없는 메모성 명사구**("나중에 참고할 사이트") — 메모
   신호(요청 동사/구매 동사/키워드)가 하나도 없으면 분류되지 않습니다.
   "메모가 될 법한 명사구는 모두 인식"하도록 넓히면 잡담까지 메모로
   오분류할 위험이 커서 보수적으로 유지했습니다.
4. **"OO한테/에게/께 전화" 패턴의 오탐 가능성** — "친구한테 전화 오면
   알려줘"처럼 실제로는 용무가 아닌 문장도 이 패턴에 걸릴 수 있습니다.
   150문장 검증에서는 실제로 나타나지 않았지만, 구조적으로 남아있는
   위험입니다.
5. **행정구역 오인식(이전 턴에서 발견, 미해결)** — "친구"류 일반 단어
   오인식은 이전 턴에서 이미 수정했으나, 유사한 다른 사례가 잠재할 수
   있습니다.

## 8. V1 출시 가능 여부 판단

**출시 가능(조건부).**

- 전체 정확도(정확+허용) 98.0%, 정확만 봐도 91.3%로 목표(90% 이상)를
  초과 달성했습니다.
- 명확한 일정 100%, 나의 하루 목표 96.2%로 목표(95% 이상)를 충족했습니다.
- 남은 3건의 한계는 모두 (a) 빈도가 낮은 캐주얼 표현이거나 (b) 사용자가
  직접 카테고리를 수정할 수 있는 기존 UI 흐름으로 충분히 보완 가능한
  수준입니다(ASON Connect는 분류 후에도 사용자가 카드를 수정할 수 있어,
  오분류가 곧바로 데이터 손실로 이어지지 않습니다).
- 기존 366개 테스트가 모두 유지된 채로 150개 신규 검증까지 통과했습니다.

다만 아래는 V1 이후 개선 과제로 남겨둡니다.
- 동점 처리 구조 개선(2건 이상 반복되면 우선순위 검토)
- 메모 카테고리의 "무동사 명사구" 인식 방식 재설계
- 한국어 형태소 분석 없이 정규식만으로 처리하는 현재 구조의 근본적 한계
  (불규칙 활용, 캐주얼 어미 등)는 V2에서 별도 접근이 필요할 수 있습니다.
